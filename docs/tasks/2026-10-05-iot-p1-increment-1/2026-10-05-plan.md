# 增量 1 实施计划

依赖顺序：Task 0 → 1 → 2 →（3、4 可并行，均依赖 2）→ 5 → 6 → 7。

## 贯穿约束

**C1 Broker 不可达不得阻断应用启动。** iot 域的 MQTT provider 连接失败时只记 `warn` 并交给 mqtt.js 自动重连，**永不抛错**。仓库有三条链路在不提供 EMQX 的情况下启动应用：本地 server 镜像冒烟（`scripts/ops/server-smoke.sh` 只注入 DATABASE_URL / REDIS_URL / JWT / ADMIN_INIT_PASSWORD）、CI 的 `docker-build` job server 冒烟（同源脚本）、CI 的 `e2e-web-real` job（后台 `node apps/nestjs-server/dist/main.js`）。任一处抛错则三条链路全挂。这也是生产姿态：接入子系统不应拖垮 API 服务。

**C2 `MQTT_URL` 三处同步。** `src/config/env.schema.ts`（默认 `mqtt://127.0.0.1:1883`，不给必填以免破坏既有 dev 与冒烟链路）、`docker-compose.yml` 的 server 服务（`mqtt://emqx:1883`，否则容器内默认值指向容器自己）、`turbo.json` 中依赖它的任务 `env` 数组。

- 确认宿主 1883 / 18083 端口未被占用。

- **验收**：`docker compose config` 通过；EMQX 容器可起并 healthy。

## Task 1 compose 与开发环境脚本

- `docker-compose.yml` 新增 `emqx` 服务：
  - 镜像精确 digest pin，注释沿用既有格式 `# pin: <日期> (pnpm ops:check-digests quarterly)`
  - 端口 `127.0.0.1:1883:1883`、`127.0.0.1:18083:18083`（只绑本机，见 D2）
  - `emqx-data` 卷、`restart: unless-stopped`、官方健康检查
  - Dashboard 初始密码从 `.env` 注入，必填（`${VAR:?}` 形态与既有 postgres 密码一致）
- `server` 服务补 `MQTT_URL: mqtt://emqx:1883`（C2）。
- `.env.example` 增加 `EMQX_DASHBOARD_PASSWORD` 与 `MQTT_URL` 两项。
- `scripts/ops/env-up.sh` 扩为三服务（postgres + redis + emqx），健康等待与输出同现有风格；`scripts/ops/env-down.sh --clean` 的卷清理覆盖 `emqx-data`。
- **卷与密码的既有行为**：`dashboard.default_password` 只在首次启动（数据卷为空）时生效。改了 `.env` 中的密码后需先 `pnpm ops:env-down --clean` 重建卷，否则仍是旧密码。
- **验收**：`pnpm ops:env-up` 跑通；`docker compose ps` 三服务 healthy；Dashboard 可用 `.env` 中的密码登录。

## Task 3 模拟器 v0

- 新建 `apps/iot-simulator`（第五个 workspace 应用）：独立 `package.json`（`mqtt` 走 `catalog:`）、tsconfig 引用 `@multi-admin/tsconfig`、eslint 引用 `@multi-admin/eslint-config`。
- 脚本 `dev` / `build` / `typecheck` / `lint` / `test`，与其它应用同形。`dev` 命名使 `pnpm dev`（turbo 全量 dev）连带启动模拟器——这是"起全平台"的一致语义；根 `package.json` 另加 `dev:sim` 便于单起。
- 单进程建立 100 条 MQTT 连接（`sim-001` … `sim-100`），每设备 1 Hz 上行 telemetry，载荷按 D3 契约生成（温度 / 振动 / 电流三测点，值在合理区间内抖动），连接串读 `MQTT_URL`。
- 单测覆盖载荷生成器（形状与值域断言），避免"新应用零测试"成为先例。
- README 写明主题与载荷格式、启动方式、如何改设备数与频率。
- `mqtt` 依赖进根 catalog（被 server 与 simulator 两端消费，满足 catalog 判据）；已核实 2026-10-05：`mqtt` 5.16.0、MIT、2026-09-16 有更新。
- **验收**：`pnpm --filter @multi-admin/iot-simulator run dev` 后，EMQX Dashboard 显示 100 个在线客户端。

## Task 4 nestjs-server iot 域

- 新增 `src/modules/iot/`，按域聚合模式组织（`iot.module.ts` 聚合 leaf，`app.module.ts` 只 import 聚合），与 `SystemModule` 同形；`PrismaModule` 为 `@Global()`，无需重复 import。
- MQTT 订阅用 `mqtt` 包自建 NestJS provider（`OnModuleInit` 连接并订阅 `wewant/devices/+/telemetry`，依赖其自动重连），不使用 `@nestjs/microservices` 的 MQTT transport——后者是 RPC / 事件总线语义，与"通配订阅设备上行"错配，且增量 2 的 BullMQ 要挂在消息处理处。**启动容错遵守 C1**。
- 日志两层：`debug` 逐条输出单报文；`info` 每秒一行聚合（收到条数、覆盖设备数）。聚合行即验收证据。
- `MQTT_URL` 按 C2 三处同步。
- 相对导入带 `.js` 后缀；错误抛 `BizException(BizCode)`。
- **验收**：后端启动后日志出现每秒聚合行；停掉 EMQX 再启动，服务不退出，且能看到重连日志。

## Task 5 测试

- 单测：载荷解析与聚合统计抽为纯函数独立覆盖；MQTT 客户端以可注入接口包装，用假实现覆盖连接与消息分发。
- e2e：新增用例连真实 EMQX（本地前置 `docker compose up -d emqx`），验证 connect → subscribe → 收到消息 → 出日志。
- CI：emqx service 加到 **`coverage` job**（服务端 e2e 在该 job 内执行 `turbo run test:coverage --filter=@multi-admin/nestjs-server`），并在该 job 的 `env` 增加 `MQTT_URL`；service 镜像同样精确 digest pin。`docker-build` 与 `e2e-web-real` 不需要 emqx——由 C1 保证不阻断。
- **验收**：`pnpm --filter @multi-admin/nestjs-server run test:coverage` 不低于 80% 门禁。
