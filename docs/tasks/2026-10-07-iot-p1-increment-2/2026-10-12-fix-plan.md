## 第一组 · 阻断与数据安全

### F1 部分成功 ⇒ 整批重投（不再 ack）

- **改**：`apps/iot-worker/src/consumer.ts` 的 `flushOnce()`
  - 现在是：`affected < deduped.length` ⇒ 只 `logger.warn`，然后**照样 resolve（＝ack）**
  - 改成：⇒ **抛错**，走已有的 `catch` 分支（作废连接 + `waiter.reject`）⇒ 消息回队列，由 BullMQ 指数退避重试
- **依据**：决策 2 §6 轴 8、§9——`affectRows` 不给行级定位，"丢弃失败那行、ack 其余"**技术上做不到** ⇒ **整批重投是唯一可执行处置**；幂等（`(子表, ts)` 覆盖）保证已成功的行不会被重复写
- **顺带**：`this.written += deduped.length` 改到只有成功时才累加（现在记的是"提交数"，失败也涨）
- **验收**：单测——mock writer 返回 `affected < 提交数` ⇒ **断言这个 Promise 被 reject**（而不是 resolve）；e2e——制造一次部分成功，断言消息重投且不丢

### F2 本地缓冲：drain 与 append 互斥

- **改**：`apps/nestjs-server/src/modules/iot/telemetry/telemetry-spill.ts` + `telemetry-producer.ts`
  - 现状：`drain()` 先 `readFile` 快照 → 逐行 `await send` → `writeFile(remaining)` **整文件重写**；而 `draining` 标志**只防 drain 与 drain、不防 append**
  - ⇒ `await send` 期间被 `spillOnly → append` 追加的新行，**被那次 `writeFile` 覆盖掉**；`this.bytes` 也跟着算错、**超限守卫失灵**
  - **改法**：让 `append` 与 `drain` 走**同一条串行链**（与 `consumer` 的 `flushChain` 同形：`this.chain = this.chain.then(...)`），或给 `drain` 加"读—改—写"临界区
- **验收**：单测——在 `drain` 的 `send` 中途调用 `append`，断言**两行都在**（现状会丢新追加的那行）

### F3 失败分类：A / B 两类 + `Table does not exist` 单独提级

- **改**：`apps/iot-worker/src/consumer.ts` 的 `worker.on('failed')` 与写入异常处理
  - **读 `TaosResultError.code`**（现在从不读）——错误里带码的走码判定，不带的按形态归类
  - **A 类（可重试）**：连接类、超时（`0x80000019` 属"可能已成功"⇒ **必须重试，不能丢弃**）⇒ 交给 BullMQ 退避
  - **B 类（重试无意义）**：格式、权限、表结构 ⇒ 耗尽次数后进 failed 集合（＝"待人工看"）+ 告警**带错误码**
  - ⭐ **`Table does not exist` 的告警级别高于其它 B 类**——正常路径下它不该出现（预建 + 不带 `USING`），一旦出现只可能是**建表遗漏**或**命名逻辑 bug**，两者都是"平台侧自己错了"
- **验收**：单测覆盖三类判定（含"不带错误码的 C 源码路径"形态，见决策 2 §10 N4）；断言 `Table does not exist` 走了提级告警

### F5 降采样环

按 [设计](2026-10-12-downsample-design.md) §3 实现，落点 `apps/iot-worker/src/downsample/`（新目录）：

| 子系统 | 要点 |
| --- | --- |
| **调度** | BullMQ Job Scheduler，队列 **`iot-telemetry-downsample`**（⚠️ 不能带冒号），三条：`ds-1m`/`every 60s`、`ds-1h`/`every 3600s`、`ds-1d`/`pattern '0 8 * * *'` + `tz: Asia/Shanghai` |
| **窗口范围** | 纯函数：给定 `nowMs` / `W` / offset / `K` ⇒ `[startMs, endMs)`，`endMs` 取最后一个**已闭合**窗口的右边界 |
| **读** | 设计 §3.3 的查询（**已实测**）。⚠️ 边界**一律用 epoch 毫秒**（字符串会被按服务器时区解释、查空）；`COUNT(<metric>)` 不是 `COUNT(*)` |
| **写** | 复用 `TdengineWriter` 的思路（预建子表 + STMT + **不带 `USING`**）。DS 的列与原始库不同 ⇒ **把 writer 的列描述从"硬编码 `RAW_METRICS`"泛化出来**，而不是复制一份 |
| **幂等** | `(子表, ts)` 覆盖 —— 与原始库同一条不变量 |
| **并发** | worker 并发 **1**；三级**平级**、互不依赖 |
| **开关** | `DOWNSAMPLE_ENABLED`（默认 `true`）、`DOWNSAMPLE_LOOKBACK_WINDOWS`（默认 `3`） |

- ⚠️ **已知不在本任务内**：平级 → 链式（要补"补传传导"）**留到触发点**（设计 §8）
- **验收**：起模拟器数分钟 ⇒ 三级表**都有数据**；对同一 `(子表, 窗口)` 手工跑一遍设计 §3.3 的查询，**逐字段与降采样表相等**

### F6 判据②改为逐条对账

- **新增脚本**：`apps/iot-worker/scripts/downsample-verify.ts`（或 `.sh`）
  - 对最近 N 个窗口，把"原始表按子表窗口聚合"与"降采样表"**逐字段 JOIN 比对**，不等即报出 `(子表, 窗口, 字段, 期望, 实际)`
- ⚠️ **不许用 `COUNT(DISTINCT …)`**（C11）
- **验收**：故意把降采样表的一行改错，脚本**必须报出来**（否则它就是又一次"看起来通过"）
